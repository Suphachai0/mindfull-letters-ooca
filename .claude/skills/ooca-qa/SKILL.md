# OOCA V.2 — QA

ตรวจงานให้ตรงกับเกณฑ์ที่กำหนดไว้แล้ว แก้จุดผิด และส่งรายงานให้ Knowledge agent ทำเป็นบทเรียนไม่ให้ผิดซ้ำ

**หลักสำคัญ: สงสัยให้ถาม ห้ามคิดเอง** ถ้าเกณฑ์ไม่ได้ระบุไว้ชัด ไม่แน่ใจว่าผิดหรือไม่ หรือไม่แน่ใจว่าควรแก้เป็นค่าอะไร ให้ถามผู้ใช้

## ทำงานเมื่อไร

อัตโนมัติ **ทุกครั้งหลังสร้างหรือแก้งาน** ก่อนส่งให้ผู้ใช้ ได้แก่
- preview หรือ frame ใน Figma ที่ได้จาก `ooca-wireframe`
- โค้ด UI
- ภาพ หรือ prompt สร้างภาพ Mooca / Sunny / สติ๊กเกอร์
- เมื่อได้รับรายงาน "Psych Review (UI)" จาก `ooca-psych-review`

จดหมายตอบของตัวละคร, system prompt และ character bible **ไม่อยู่ในขอบเขตของ skill นี้** ให้ `ooca-psych-review` ตรวจแทน

## เกณฑ์ที่ใช้ตรวจ (อ่านก่อนเริ่มทุกครั้ง)

| ลำดับ | แหล่ง | ใช้ตรวจ |
|---|---|---|
| 0 | [LESSONS.md](LESSONS.md) | จุดที่เคยผิดมาแล้ว ตรวจข้อเหล่านี้ก่อน |
| 1 | [ooca-design-system](../ooca-design-system/SKILL.md) | สี ฟอนต์ shapes ปุ่ม ไอคอน background elevation โลโก้ |
| 2 | [mooca-character](../mooca-character/SKILL.md) | รูปทรง เส้น สี สีหน้า ท่า ขนาด ของ Mooca / Sunny |
| 3 | [ooca-wireframe](../ooca-wireframe/SKILL.md) | ขั้นตอนและข้อกำหนดของ wireframe / หน้าจอ |
| 4 | [KNOWLEDGE.md](../../../KNOWLEDGE.md) หัวข้อ ✅ | คอนเซ็ปต์ กลุ่มเป้าหมาย User Flow ความจำตัวละคร design system |
| 5 | [KNOWLEDGE.md](../../../KNOWLEDGE.md) หัวข้อ 💡 | ข้อเสนอที่ยังไม่ยืนยัน (ใช้ตรวจได้ แต่แก้ต้องถามก่อน) |
| 6 | [ooca-psych-review](../ooca-psych-review/SKILL.md) ข้อ 7 | ข้อความบน UI (ใช้เป็นเกณฑ์บังคับ แก้ได้ทันที) |

- ใช้ค่าจากไฟล์เหล่านี้ตรงตัว ห้ามจำค่าเอาเอง ให้เปิดไฟล์ดูทุกครั้ง
- จุดที่ไฟล์ Figma ขัดกันเอง ให้ยึดตามหัวข้อ "จุดที่ต้องระวัง" ใน `ooca-design-system` (เช่น Typography ยึดตัวเลขที่กำกับ, Elevation ยึด effect จริง)

## จะแก้เลย หรือถามก่อน

| กรณี | ทำอย่างไร |
|---|---|
| ผิดจากค่าที่ skill (ข้อ 1–3, 6) หรือหัวข้อ ✅ ระบุไว้ชัดเจน | **แก้ทันที** |
| ขัดกับหัวข้อ 💡 ใน KNOWLEDGE.md | **ถามก่อนแก้** |
| เกี่ยวกับหัวข้อ ❓ (คำถามค้าง) เช่น โทนภาพ บทบาท Mooca ฟอนต์ลายมือ | **ถามก่อนแก้** |
| เรื่องที่ skill ไม่ได้ระบุไว้ เช่น รัศมีมุม avatar (ยังไม่ระบุใน design system) | **ถามก่อนแก้** |
| แหล่งเกณฑ์ขัดกันเอง เช่น พาเลต Mooca กับ design system, Mooca flat vector กับโทน Ghibli | **ถามก่อนแก้** และบอกว่าขัดกันระหว่างข้อไหนกับข้อไหน |
| ไม่แน่ใจว่าผิดหรือไม่ | **ถาม** |

ข้อจำกัดตอนแก้:
- แก้ใน Figma ได้เฉพาะ frame ที่ผู้ใช้อนุมัติและสร้างไปแล้วตาม `ooca-wireframe` ห้ามสร้าง frame ใหม่ ห้ามแตะหน้า CI
- ก่อนเรียก `use_figma` ต้องโหลด skill `figma:figma-use` ตามที่ `ooca-wireframe` กำหนด
- แก้เสร็จแล้วให้ตรวจซ้ำจุดที่แก้ (Figma ใช้ `get_screenshot`) จนผ่าน

## Checklist

ตรวจทุกข้อที่เกี่ยวกับประเภทงานนั้น ค่าละเอียดดูในไฟล์เกณฑ์

### A. งานดีไซน์ใน Figma / preview

**Design system**
- [ ] สีทุกสีมีในหัวข้อ Color (รวม palette 50–900) ไม่มีสีที่คิดขึ้นเอง
- [ ] ข้อความใช้ text style ตามตาราง Typography: EN = Gotham Rounded, TH = Prompt · size / line-height / weight ตรง · letter-spacing 0
- [ ] ปุ่มใช้ component set `Button/In card only` เลือก Type / State / Size / Colors / Language ถูก · สีตาม State ตรงตารางสีปุ่ม · มุม 50 px
- [ ] ไอคอนเป็น `Icon/...` ที่อยู่ในรายชื่อ ขนาดอยู่ในชุด 12/16/20/24/40/56/72 (หลัก 24)
- [ ] Shapes: สิ่งที่กดได้ (button, dialog, card, input) มุม 8 หรือ 24 px และไม่ชนขอบ · พื้นที่แบ่ง layout เป็นมุมเหลี่ยมชนขอบ · ไม่ใช้มุมเหลี่ยมกับ action / avatar / metadata · circle ใช้กับ control
- [ ] เงาใช้ Elevation 01–08 ตามค่าจริง (สี Turquoise) เท่านั้น
- [ ] Background ใช้ `Background/Default` หรือ `Background/Gradient/Extended`
- [ ] โลโก้ "mindfull" ใช้ไฟล์จาก Figma และใช้สีตามพื้นหลังที่กำหนด ไม่วาดหรือพิมพ์ใหม่
- [ ] ใช้ variable / style ที่มีในไฟล์ ไม่ใช้ค่า hard-code (เฉพาะใน Figma)

**Wireframe**
- [ ] มีทั้งมือถือ 375 × 812 และ Desktop กว้าง 1440
- [ ] ข้อความเป็นภาษาไทยจริงตามบริบทโปรเจกต์ ไม่มี lorem ipsum
- [ ] มีทุก state ที่หน้าจอต้องมี (ว่าง / กำลังโหลด / error / disabled) ถ้าไม่แน่ใจว่าครบหรือไม่ ให้ถาม
- [ ] ภาพประกอบ / ตัวละคร / สติ๊กเกอร์ที่ยังไม่มีไฟล์จริง เป็นกล่อง placeholder มีป้ายกำกับ
- [ ] ชื่อ frame แบบ `Mobile / <ชื่อหน้า>` และ `Desktop / <ชื่อหน้า>` วางคู่กัน
- [ ] อยู่ในหน้า (page) ที่ผู้ใช้เลือก ไม่ใช่หน้า CI
- [ ] Figma ตรงกับ preview ที่ผู้ใช้อนุมัติ

**KNOWLEDGE.md**
- [ ] ลำดับหน้าจอตรงกับ User Flow (✅)
- [ ] เนื้อหา ฟีเจอร์ หรือ flow ที่ไม่มีใน KNOWLEDGE.md → ถาม
- [ ] เทียบกับ 💡 ที่เกี่ยวข้อง: มือถือมาก่อน, ข้ามหรือเร่งแอนิเมชันได้, ข้อความค่อยๆ แสดง (ปรับความเร็ว / แตะแสดงทั้งหมด / screen reader), ความปลอดภัยและความเป็นส่วนตัว (หัวข้อ 6–7)

### B. โค้ด UI

- [ ] สี HEX ตรงกับ design system ทุกค่า
- [ ] `font-family`: EN `'Gotham Rounded', 'Prompt', sans-serif` · TH `'Prompt', sans-serif` · size / line-height / weight ตาม Typography · `letter-spacing: 0`
- [ ] `box-shadow` ตรงกับตาราง Elevation ทุกตัวอักษร
- [ ] `border-radius`: ปุ่ม 50px · สิ่งที่กดได้ 8px หรือ 24px
- [ ] ขนาดปุ่มและสีตาม State ตรงกับหัวข้อ Button
- [ ] Background gradient ตรงกับ CSS อ้างอิงใน design system
- [ ] ไอคอนมาจากชุด `Icon/...` ใน Figma
- [ ] ข้อความภาษาไทยจริง ไม่มี lorem ipsum
- [ ] รองรับมือถือก่อน (💡 — ถ้าไม่ตรง ให้ถาม)

### C. ภาพ / prompt Mooca และสติ๊กเกอร์

- [ ] flat vector สีทึบ ไม่มี gradient ไม่มี texture ไม่มีลายเส้นสเก็ตช์
- [ ] ไม่มีเส้นขอบสีดำ ขอบเมฆใช้ `#D2DEED`
- [ ] สีทุกสีอยู่ในพาเลต Mooca / Sunny / อุปกรณ์ประกอบ
- [ ] เมฆเป็นสีขาว (อารมณ์บวก) หรือม่วงเทา (อารมณ์ลบ) เท่านั้น และตรงกับอารมณ์ของท่า
- [ ] สีหน้าตรงตามตารางสีหน้า · ไม่มีจมูก ฟัน นิ้วละเอียด · ไม่มีสีหน้ารุนแรง
- [ ] สัดส่วน chibi: หัวเมฆ ≈ 60% · มีผ้าพันคอใต้เมฆ ชายผ้าห้อยหนึ่งข้าง
- [ ] เส้น round cap / round join · ความหนาเส้นตามตาราง (ขนาด L)
- [ ] ขนาดกรอบตรงกับ L / M / S / XS
- [ ] prompt สร้างภาพมีค่าสีและข้อห้ามครบเหมือนตัวอย่างใน skill
- [ ] โทนภาพของเว็บยังเป็น ❓ → ถ้างานต้องเลือกโทน ให้ถาม

### D. ข้อความบน UI (จากรายงาน Psych Review)

- [ ] แก้ข้อความทุกข้อในรายงาน "Psych Review (UI)" ตามช่อง "ควรเป็นแบบไหน" ในทุกที่ที่ข้อความนั้นปรากฏ (Figma และโค้ด)
- [ ] ข้อความที่แก้แล้วยังผ่าน checklist ข้อ 7 ของ `ooca-psych-review`
- [ ] ถ้าช่อง "ควรเป็นแบบไหน" ไม่ได้ให้ข้อความที่ใช้ได้ทันที หรือแก้แล้วกระทบ layout ให้ถาม
- [ ] ใส่จุดที่แก้ลงใน QA Report ให้ Knowledge agent ด้วย (อ้างอิง: ooca-psych-review § 7)

## รายงานให้ Knowledge agent

ไม่ต้องแสดงรายการจุดผิดให้ผู้ใช้ ให้ส่งรายงานนี้ให้ **Knowledge agent** ตรวจและบันทึกลง [LESSONS.md](LESSONS.md)
ส่งทุกครั้งที่พบจุดผิดอย่างน้อย 1 จุด ถ้าไม่พบเลยไม่ต้องส่ง

```markdown
## QA Report — <YYYY-MM-DD> — <ชื่องาน>

ประเภทงาน: <Figma / โค้ด UI / Mooca / ข้อความ UI>
ตำแหน่ง: <ชื่อ frame + node id / path:line / ชื่อไฟล์ภาพ>

| # | จุดที่ผิด | ค่าที่เจอ | ค่าที่ถูก | อ้างอิง | สถานะ |
|---|---|---|---|---|---|
| 1 | สีปุ่ม Primary Turquoise ตอน Active | `#26CDBE` | `#4DD6CA` | ooca-design-system § 8 Button | แก้แล้ว |
| 2 | ... | ... | ... | KNOWLEDGE.md § 8 (💡) | รอผู้ใช้ตอบ |

สาเหตุที่น่าจะผิด: <เช่น จำค่าเอาเองแทนเปิดไฟล์, สับสน Active กับ Loading>
ข้อเสนอบทเรียน: <ประโยคสั้นๆ ที่ช่วยไม่ให้ผิดซ้ำ>
```

- **อ้างอิง** ต้องระบุชื่อไฟล์และหัวข้อ (§) เสมอ
- **สถานะ:** แก้แล้ว · รอผู้ใช้ตอบ · ผู้ใช้ให้คงไว้

## สิ่งที่ห้ามทำ

- แก้จุดที่อยู่นอกเหนือ skill ที่กำหนด หรือขัดกับ 💡 / ❓ โดยไม่ถาม
- ใช้ค่าจากความจำหรือคิดค่าขึ้นมาเองแทนการเปิดไฟล์เกณฑ์
- แก้ไฟล์ skill อื่น หรือ KNOWLEDGE.md (KNOWLEDGE.md แก้ได้เมื่อผู้ใช้ยืนยันตาม CLAUDE.md เท่านั้น)
- เขียน LESSONS.md เอง (เป็นหน้าที่ของ Knowledge agent)

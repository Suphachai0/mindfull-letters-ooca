# OOCA V.2 Wireframe Workflow

**หลักสำคัญ: preview ในแชท → แก้ไข → ผู้ใช้อนุมัติ → ค่อยสร้างใน Figma**
ห้ามเขียนลง Figma ก่อนที่ผู้ใช้จะพิมพ์อนุมัติชัดเจน

## ข้อมูลที่ต้องใช้ (อ่านก่อนเริ่มทุกครั้ง)

1. [KNOWLEDGE.md](../../../KNOWLEDGE.md): คอนเซ็ปต์ กลุ่มเป้าหมาย User Flow ตัวละคร ความปลอดภัย ความเป็นส่วนตัว UX ขอบเขต MVP
2. skill `ooca-design-system` ([SKILL.md](../ooca-design-system/SKILL.md)): สี ฟอนต์ shapes ปุ่ม ไอคอน background elevation
3. ยึดหัวข้อ ✅ ใน KNOWLEDGE.md เป็นหลัก ถ้าหน้าจอต้องขัดกับข้อเหล่านั้น ให้บอกผู้ใช้ตรงๆ ว่าขัดกับข้อไหน
4. ถ้าข้อมูลไม่พอหรือมีหลายทางเลือก (เช่น เนื้อหาบนหน้า, ลำดับขั้น, ข้อ ❓ ที่ยังค้าง) **ให้ถามผู้ใช้ ห้ามคิดเอง**

## ระดับความละเอียด

ใช้ข้อมูลทั้งหมด และละเอียดทุกประการ (ผู้ใช้กำหนด):
- สี ฟอนต์ ขนาดตัวอักษร line-height ปุ่ม ไอคอน มุมโค้ง เงา และพื้นหลัง ต้องตรงกับ `ooca-design-system` ทุกค่า
- ข้อความบนหน้าจอเป็นภาษาไทยจริงตามบริบทของโปรเจกต์ ไม่ใช้ lorem ipsum
- ใส่ทุก state ที่หน้าจอนั้นต้องมี (เช่น ว่าง / กำลังโหลด / error / disabled) ถ้าไม่แน่ใจว่าต้องมี state ไหน ให้ถาม
- ภาพประกอบ ตัวละคร หรือสติ๊กเกอร์ที่ยังไม่มีไฟล์จริง ให้วางเป็นกล่อง placeholder พร้อมป้ายบอกว่าเป็นอะไร ห้ามวาดขึ้นเองให้ดูเหมือนของจริง
- ใช้เฉพาะไอคอนที่มีในรายชื่อของ design system (อ้างชื่อ component เช่น `Icon/Home/Regular`) ถ้าไม่มีไอคอนที่ต้องการ ให้ถาม

## ขนาดหน้าจอ

ทำ **ทั้งมือถือและ Desktop** ทุกหน้าจอ ทำมือถือก่อน:
- **มือถือ:** 375 × 812
- **Desktop:** 1440 กว้าง (ความสูงตามเนื้อหา)

## ขั้นที่ 1 — Preview ในแชท

1. สรุปสั้นๆ ก่อนวาด: หน้าจอนี้คืออะไร อยู่ขั้นไหนของ User Flow มีองค์ประกอบอะไรบ้าง
2. แสดงเป็น **ภาพ mockup ในแชท** ด้วยเครื่องมือ `show_widget` (เรียก `read_me` ก่อนครั้งแรกตามที่เครื่องมือกำหนด)
   - วางมือถือกับ Desktop คู่กันในภาพเดียว หรือแยกเป็นสองภาพ
   - เขียนสีเป็น HEX จาก design system ตรงๆ
   - ฟอนต์: `font-family: 'Gotham Rounded', 'Prompt', sans-serif` สำหรับ EN และ `'Prompt', sans-serif` สำหรับ TH
   - ใส่หมายเลขกำกับจุดสำคัญได้ ถ้าช่วยให้ผู้ใช้อ้างถึงตอนสั่งแก้ได้ง่ายขึ้น
3. ใต้ภาพ เขียนรายการสั้นๆ ว่าใช้ token อะไร (เช่น ปุ่ม `Primary / Turquoise / Default`, หัวข้อ `H3/TH`, เงา `Elevation 03`) และจุดที่ยังต้องให้ผู้ใช้ตัดสินใจ
4. ถามผู้ใช้ด้วยปุ่มใน wrap_up เช่น "อนุมัติ" / "แก้ไข"

## ขั้นที่ 2 — แก้ไข

- แก้ตามที่ผู้ใช้สั่ง แล้วแสดง preview ใหม่ทั้งภาพทุกครั้ง
- บอกสั้นๆ ว่ารอบนี้เปลี่ยนอะไร
- ถ้าคำสั่งแก้ขัดกับ design system หรือหัวข้อ ✅ ใน KNOWLEDGE.md ให้บอกก่อนแก้
- วนจนกว่าผู้ใช้จะอนุมัติ

## ขั้นที่ 3 — สร้างใน Figma (หลังอนุมัติเท่านั้น)

1. **ถามผู้ใช้ทุกครั้งว่าจะวางลงหน้า (page) ไหน** ในไฟล์ OOCA-V.2 (fileKey `jctrN3IDLbVHznhZz90CpC`) ห้ามเลือกเอง และห้ามวางลงหน้า CI ยกเว้นผู้ใช้สั่ง
2. โหลด skill `figma:figma-use` ก่อนเรียก `use_figma` ทุกครั้ง (และ `figma:figma-generate-design` สำหรับประกอบทั้งหน้าจอ) แล้วเรียก `create_session` กับไฟล์นี้
3. ใช้ของจริงจากไฟล์ แทนการวาดใหม่:
   - ปุ่ม: component set `Button/In card only` (node `1:3034`) เลือก variant ให้ตรงกับ preview
   - ไอคอน: component `Icon/...` จากหน้า Icon (node `1:2309`)
   - สี และ text style: ใช้ variable / style ที่มีอยู่ในไฟล์ (เช่น `Main Colors/Other Colors/Turquoise`, `H3/TH`, `Body1/EN`)
   - Background: `Background/Default` หรือ `Background/Gradient/Extended`
4. ตั้งชื่อ frame ให้อ่านรู้เรื่อง เช่น `Mobile / เขียนจดหมาย` และ `Desktop / เขียนจดหมาย` วางมือถือกับ Desktop ไว้ข้างกัน
5. ตรวจผลด้วย `get_screenshot` แล้วเทียบกับ preview ที่อนุมัติ แก้จนตรง
6. ส่งลิงก์ frame ใน Figma ให้ผู้ใช้ และบอกถ้ามีจุดที่ไม่ตรงกับ preview พร้อมเหตุผล

## สิ่งที่ห้ามทำ

- สร้างหรือแก้ใน Figma ก่อนผู้ใช้อนุมัติ preview
- ใช้สี ฟอนต์ ขนาด หรือเงาที่ไม่มีใน `ooca-design-system`
- เลือกหน้า Figma เอง
- เดาเนื้อหา ฟีเจอร์ หรือ flow ที่ไม่มีใน KNOWLEDGE.md โดยไม่ถาม

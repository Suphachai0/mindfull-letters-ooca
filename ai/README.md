## Flow ของจดหมาย 1 ฉบับ

```
ผู้ใช้เลือกสติ๊กเกอร์
  │
  ├─ 1. บันทึกจดหมายลง DB (ต้องทำก่อนเสมอ)
  │
  ├─ 2a. คัดกรองวิกฤต (crisis-screening.md)  ─┐  เรียกพร้อมกัน
  └─ 2b. เขียนจดหมายตอบ (shared-rules + ตัวละคร + ความจำ)  ─┘
           │
           ▼
  3. ตรวจผล
     - คัดกรองได้ high/imminent → หยุดแอนิเมชัน แสดงหน้าช่วยเหลือ
       ถ้าจดหมายตอบไม่ได้เขียนแบบโหมดวิกฤต → เขียนใหม่ด้วย <mode>crisis</mode>
     - อื่นๆ → แสดงจดหมายตอบตามปกติ
  │
  ▼
  4. สรุปจดหมายเป็นความจำ (memory.md) ทำหลังแสดงผลแล้ว ไม่ต้องรอ
```

ข้อ 2a และ 2b เรียกพร้อมกันตามที่บันทึกไว้ใน KNOWLEDGE.md หัวข้อ 6 และ 9 ตัวเขียนจดหมายจึงไม่รู้ผลคัดกรองล่วงหน้า ต้องประเมินสัญญาณเองด้วย (ดู shared-rules.md หัวข้อความปลอดภัย)

## สิ่งที่ยังไม่ได้ทำในเฟสนี้

- ตัวละครตัวที่ 2–3 (คุณป้าร้านกาแฟ, แมวออฟฟิศ)
- ทดสอบกับ API จริง ไฟล์ทดสอบตอนนี้เป็นการจำลองโดยเขียนตาม prompt ด้วยมือ
- รีวิวจากนักจิตวิทยา
- การเลือกโมเดลและต้นทุนต่อฉบับ (ไว้เฟส 4)
